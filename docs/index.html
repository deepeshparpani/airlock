The Core Dilemma

The Unattended Agent Paradox

Why built-in platform "Auto Modes" fail to deliver true, secure autonomy for software engineering agents.

1. The "Babysitter" Trap

Built-in platform "Auto Modes" sandbox routine commands, but the moment an action touches a native toolchain, installs a package, accesses the network, or appears "risky," it halts and waits for manual approval.

  • Breaks unattended execution when you leave your desk.
  • Causes extreme prompt fatigue (~50 clicks per hour).
  • Cannot run overnight or in autonomous CI/CD loops.

2. The "Suicide" Mode

To bypass prompt fatigue, developers enable --dangerously-skip-permissions or always-proceed. This hands an LLM ambient root access to execute arbitrary code with zero guardrails.

  • Vulnerable to prompt injection from untrusted web pages.
  • Hallucinated lateral scripts can delete home directories (rm -rf ~).
  • Ambient extraction of SSH keys, AWS credentials, and keychains.

3. The Airlock Solution

Airlock places a deterministic, sub-millisecond security mesh between the AI agent and the operating system process boundary. Developers can safely run with full unprompted autonomy.

  • Instant Microsecond Fast-Allow (<1ms) for known safe reads.
  • Zero-Tolerance Microsecond Hard-Deny for destructive/exfil actions.
  • Cascaded AI Review (<2.5s) for truly ambiguous mutations.
Systems Architecture

Multi-Tier Cascaded Defense Pipeline

Deterministic invariant evaluation at the microsecond layer, backed by semantic SLM verification and deep deliberative fail-closed escalation.

airlock-pipeline-topology.svg
Figure 2.0: Cascaded evaluation pipeline topology. Invariant security rules resolve 92%+ of commands in microseconds (<1ms), while ambiguous commands cascade into semantic confidence classifiers.

Tier 0: Deterministic Guardrails (<1ms)

Implemented in pure Rust (crates/airlock-core) with zero external allocations. Executes in ~10–40 microseconds:

  • Microsecond Prompt Injection Scanner: Rejects directive overrides (ignore instructions), roleplays, and model control tokens.
  • Hard Path Deny: Blocks reads of ~/.ssh, ~/.aws, .env, macOS Keychains, browser session cookies, and personal databases (chat.db).
  • Build Scope Restriction: Restricts rm -rf strictly to verified build artifacts (dist/, target/, node_modules/).

Stage 1: Fast SLM Filter (~2.5s)

Unresolved or complex command mutations cascade over Unix domain sockets to a warm background daemon:

  • Schema-Enforced Classification: Low-latency evaluation utilizing Gemini 3.8 Flash-Low.
  • Confidence Scoring: Emits structured verdicts with confidence: high | low.
  • Instant Short-Circuit: High-confidence allows bypass further review; low-confidence automatically escalates.

Stage 2: Deep Deliberation (<10s)

High-risk or ambiguous actions fail closed into deep multi-model deliberative review:

  • Lateral Threat Analysis: Evaluates obfuscated network interactions and multi-stage build scripts.
  • Fail-Closed Guarantee: If models disagree or timeouts occur, the command is denied by default.
  • Pre-Flight Secret Scrubbing: High-entropy tokens are redacted before leaving the host.
Engineering Rigor

Architectural Decision Records (ADRs)

Key architectural trade-offs, engineering standards, and systems invariants implemented in the Airlock codebase.

ADR-001: Zero-Overhead Compiled Rust Core with POSIX Concurrency

SYSTEMS & OS

Context & Problem: AI agent hook orchestrators run synchronously on every tool call. A typical Python interpreter launch incurs a 40ms+ cold start, adding massive friction to rapid agent loops.

Decision: We implemented the primary gatekeeper in compiled, native Rust (crates/airlock-core and crates/airlock-hook). We enforced strict POSIX concurrency invariants:

  • Kernel Singleton Locking: Non-blocking file descriptor locking via flock(LOCK_EX | LOCK_NB) to prevent concurrent daemon races.
  • Atomic Port Manifests: Process coordination using PID-tagged temporary files and atomic POSIX rename(2) replacement to guarantee zero partial-read states.
  • Universal Headless Isolation: Evaluator background processes are isolated using setsid() / process_group(0), dynamically stripping session tokens across 11 terminal emulators to eliminate GUI flashes.

ADR-002: Dual-Language Graceful Degradation (Rust Core + Python Fallback)

PORTABILITY

Context & Problem: Enterprise and remote development environments may not have a Rust toolchain or build environment pre-installed.

Decision: We adopted a dual-engine architecture: the high-performance native Rust binary provides 10.8x faster execution (~3.8ms), while an identical, pure standard-library Python package (zero external pip dependencies) serves as a universal zero-setup fallback.

ADR-003: Cryptographic Nonced Spotlighting & Delimiter Breakout Defense

AI SECURITY

Context & Problem: Untrusted command strings can contain adversarial prompt injection payloads designed to override system instructions or fool semantic classifiers.

Decision: When escalating commands to LLM stages, Airlock encloses the raw payload inside cryptographic, nonce-tagged XML tags (<untrusted_command_{nonce}>). Any occurrence of the matching closing delimiter in the payload is sanitized prior to templating, neutralizing delimiter escape attacks.

ADR-004: Diagnostic Environment Isolation vs. Credential Materialization

DLP & HYGIENE

Context & Problem: Naive security regexes flag commands like env -u OPENAI_API_KEY pytest as credential leaks because the variable name matches secret patterns, blocking legitimate test processes.

Decision: In both Rust (ENV_UNSET_RE) and Python, Airlock sanitizes -u <VAR> and --unset=<VAR> flags before evaluating credential materialization invariants. Legitimate test isolation is granted instant fast-path approval, while actual exfiltration (printenv KEY, echo $KEY, env | grep KEY) remains strictly denied.

ADR-005: AST-Canonicalized Safe Build Target Allowlisting

DESTRUCTIVE SAFETY

Context & Problem: Completely banning rm -rf prevents agents from cleaning build directories (cargo clean, rm -rf dist), while allowing it unconditionally opens the door to catastrophic data loss.

Decision: Airlock performs POSIX-compliant AST parsing of shell arguments. Deletion via rm -rf is strictly authorized only if all target arguments match an explicit allowlist of ephemeral build artifacts (dist, build, target, node_modules, __pycache__). Any target containing source code (src/), home directories (~), or wildcards (*) is hard-denied in <1ms.
